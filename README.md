# Sqoch Ticket

Демонстрационный сервис покупки билетов на мероприятия. Покупатель выбирает ивент,
указывает участников, проверяет состав и стоимость заказа и подтверждает оформление.

В панели организатора можно управлять мероприятиями, готовить рассылки, запускать
их после подтверждения и следить за результатами. Помощник через OpenRouter
предлагает изменения ивентов и готовит черновики уведомлений.

**Стек:** Go, SQLite, React, TypeScript, Vite, Nginx и RabbitMQ.
Приложение запускается через Docker Compose. Оплата не подключена, отправитель
писем работает на моковых данных. При первом запуске создаются два тестовых ивента.

## Запуск

Нужны Docker Desktop или Docker Engine с Compose v2. Выполните в корне проекта:

```sh
# Создайте .env, если его ещё нет.
cp .env.example .env

docker compose up --build
```

Если `.env` уже настроен, пропустите копирование. Все настройки хранятся в этом файле.

После запуска доступны:

- [Каталог мероприятий](http://localhost:8080).
- [Панель организатора](http://admin.localhost:8080).

Для входа в панель используйте `ADMIN_EMAIL` и `ADMIN_PASSWORD` из `.env`.
Внешний порт задаётся через `APP_PORT` (по умолчанию `8080`).
Если Compose установлен отдельной командой, используйте `docker-compose`
вместо `docker compose`.

### Помощник

Для работы чата заполните в `.env` `OPENROUTER_API_KEY` и `OPENROUTER_MODEL`
(ID модели с поддержкой инструментов), затем примените настройки:

```sh
docker compose up -d --build backend
```

Без этих настроек остальные разделы приложения работают, чат отключён.

### Тестовые покупки и демонстрация сбоя

Добавить 20 действующих и отменённых покупок для двух ивентов:

```sh
docker compose exec backend /app/api seed-orders
```

Повторный запуск команды не создаёт дубли.

Для автоматической демонстрации сбоя и восстановления рассылки нужен Python 3:

```sh
python3 scripts/demo-mailing-failure.py
```

Скрипт создаёт отдельный Docker-стенд, проверяет ошибки, перезапуск и отсутствие
повторных писем, затем удаляет созданные контейнеры и volumes. Путь к отчёту и логам
выводится в терминале. Для просмотра ошибки в админке добавьте
`--pause-on-failure --keep`; команду удаления оставленного стенда скрипт выведет в конце.

## Управление запуском

```sh
docker compose up -d --build  # запуск в фоне и применение изменений
docker compose logs -f       # логи
docker compose down          # остановка с сохранением данных
docker compose down -v       # остановка и удаление всех БД и очередей проекта
```

Данные сохраняются в Docker volumes между перезапусками.
