# Sqoch Ticket

Демонстрационный сервис оформления билетов: Go + SQLite, React + TypeScript.
Моковое мероприятие «За пределами привычного»: 21 ноября 2026, 18:00 МСК,
Москва, пространство «Орбита». Начальный запас — 100 мест.

## Запуск

Нужны Docker Engine / Desktop и Compose v2.

```sh
cp .env.example .env   # только если .env ещё нет
docker compose up --build
```

Откройте http://localhost:8080. Если Compose установлен отдельным бинарным
файлом, используйте `docker-compose` вместо `docker compose`.

```sh
docker compose up --build -d
docker compose logs -f
docker compose down       # остановка с сохранением заказов
docker compose down -v    # удаление всех демо-заказов, затем новый запуск даст 100 мест
```

## Сценарий

1. Заполните имя и возраст каждого участника, общий контактный email.
2. Проверьте состав, типы билетов и стоимость на отдельном шаге.
3. При необходимости вернитесь через «Изменить данные»: значения сохраняются.
4. Подтвердите заказ. На сервере повторно проверяется наличие мест.
5. При успехе отображаются номер заказа, участники, email и сумма; запись
   сохраняется в SQLite. Оплата и отправка писем не подключены.

Правила применяются на клиенте для удобства и независимо на сервере:

- От 1 до 4 участников, для каждого обязательны имя и целый возраст 0–120.
- До 14 лет: 1 000 ₽; с 14 лет: 2 000 ₽.
- **Любому участнику младше 18 лет** нужен участник от 18 лет в том же заказе.
  Полный тариф в 14–17 лет не отменяет это требование.
- Один обязательный контактный email на заказ.
- Итог рассчитывает сервер; клиент не передаёт цены.

### Как показать оба результата

С `DEMO_MODE=true` под формой есть раскрываемая панель «Демонстрация сценариев».

**Успех:** оставьте «Успешное оформление», введите Анна / 18 и Маша / 13,
email `anna@example.ru`. Сумма — 3 000 ₽. Перейдите к проверке и подтвердите.

**Места закончились:** на первом шаге раскройте панель и выберите
«Места закончатся». Заполните те же данные, проверьте заказ и подтвердите.
Сервер вернёт HTTP 409; появится отдельный экран с объяснением и возвратом к форме.
Введённые данные сохранятся. Кнопка «Попробовать успешный сценарий» возвращает
к участникам и отключает имитацию для следующего оформления.

Демо-ошибка относится только к выбранному черновику: она не расходует места и
не создаёт заказ. В обычном сценарии работает реальный общий запас мест в SQLite:
два параллельных заказа не смогут купить одно последнее место.
При нулевом общем запасе даже обычное оформление завершится нехваткой мест.
`down -v` сбрасывает демо-базу целиком — используйте его только если данные больше не нужны.

## Конфигурация

Корневой `.env` не включается в Git; шаблон — `.env.example`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_PORT` | `8080` | Внешний порт приложения |
| `API_PORT` | `8081` | Внутренний порт backend / upstream Nginx |
| `SQLITE_PATH` | `/data/sqoch.db` | Абсолютный путь SQLite внутри контейнера |
| `LOG_LEVEL` | `info` | debug, info, warn, error |
| `DEMO_MODE` | `true` | Панель сценариев и разрешение имитации нехватки мест |

После изменения `.env`: `docker compose up -d --build`.
Для сохранения БД оставляйте путь внутри `/data`, подключённого к именованному
volume `sqlite_data`. API доступен через Nginx по `/api`, отдельно порт backend
на хост не публикуется. Docker-сборки не используют hot reload.

## API

- `GET /api/health` — состояние API и SQLite, HTTP 200 или 503.
- `GET /api/event` — моковое мероприятие, остаток мест, тарифы и доступность демо.
- `POST /api/checkouts` — проверить правила, рассчитать цену, сохранить черновик
  на 15 минут. Места на этом шаге **не резервируются**.
- `POST /api/checkouts/{id}/confirm` — атомарно списать места и создать заказ.
  Повторное подтверждение того же черновика возвращает тот же заказ.

Пример тела создания черновика:

```json
{
  "email": "anna@example.ru",
  "participants": [
    {"name": "Анна", "age": 18},
    {"name": "Маша", "age": 13}
  ],
  "simulate_sold_out": false
}
```

Ответ содержит `id`, `email`, рассчитанных `participants` (тип и цена каждого),
`total` в целых рублях и `expires_at`. Подтверждение принимает пустой объект `{}`
и возвращает `id`, `number`, `email`, `participants`, `total`, `created_at`.
Непрозрачный случайный идентификатор черновика не следует публиковать: в этом
демо он даёт возможность подтверждения без авторизации.

Ошибки: `400 invalid_request`, `422 validation` с ошибками полей,
`409 sold_out`, `410 expired`, `404 not_found`, `503 unavailable`.
Лишние поля (в том числе подставленные цены) не принимаются.
После потери ответа подтверждение повторяется с тем же ID; редактирование
заблокировано до получения результата, чтобы не создать новый заказ случайно.

## Архитектура

```text
backend/
  cmd/api/                       сборка зависимостей и жизненный цикл
  internal/domain/               тарифы, правила возраста, сущности
  internal/usecase/              сценарии оформления, интерфейс репозитория
  internal/delivery/http/        JSON API, HTTP-коды и ошибки полей
  internal/infrastructure/
    config/                      проверка окружения
    sqlite/                      миграция, моковое событие, транзакции
frontend/
  src/
    App.tsx                      шаги формы и результаты
    api.ts                       запросы, таймауты, ошибки API
    types.ts                     типы и клиентская валидация
    components/                  шапка, состав и стоимость
    styles.css                   общие токены и темы
    booking.css                  адаптивный сценарий оформления
  public/                        локальные шрифты и логотип
  nginx/                         статика и прокси API
```

SQLite без CGO, WAL и foreign keys. При запуске в транзакции создаются таблицы
`events`, `checkouts`, `orders`; повторный запуск не сбрасывает остаток или заказы.
Подтверждение выполняет условный UPDATE остатка и INSERT заказа в одной транзакции.
Уникальность `checkout_id` в orders и повторное чтение результата защищают от дублей.
Сервер пишет JSON-логи и корректно закрывает HTTP и БД по SIGTERM/SIGINT.

## Проверки

Нужны Go 1.25+ и Node.js 24 с npm.

```sh
(cd backend && go test -race ./... && go vet ./...)
(cd frontend && npm ci && npm test && npm run build)
```

Тесты покрывают границы 13/14/17/18, младенца с сопровождающим, ограничения
числа участников, поля, защиту цен, idempotent confirmation, одновременную
покупку последнего места, истечение черновика, отключение демо и отсутствие
заказа при нехватке мест. Используется временная SQLite, рабочая БД не затрагивается.

Ручные проверки: 360px и desktop, обе темы, добавление/удаление до 4 человек,
17-летний без взрослого, 18-летний + ребёнок, редактирование перед подтверждением,
успешный результат, нехватка мест, повторный запрос после сетевой ошибки.

## Дизайн

`design.md` описывает систему, извлечённую из sqoch.com: обе палитры, Manrope,
градиенты, радиусы и компоненты. Шрифты и логотип локальные; лицензия Manrope —
`frontend/public/fonts/OFL.txt`. Переключатель темы сохраняет выбор в браузере.
Данные участников, шаг и результат сохраняются в sessionStorage текущей вкладки,
поэтому обновление страницы не сбрасывает оформление. Постоянный localStorage
используется только для темы. После закрытия вкладки сессия зависит от политики
восстановления браузера; подтверждённые заказы сохраняются на сервере.
При недоступности хранилища оформление работает без автосохранения.
